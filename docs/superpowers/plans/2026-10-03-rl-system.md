# Jev forecasting and RL system implementation plan

**Status: original staged design, with a subsequently authorized MARKET_ONLY implementation.** The user requested actual neural evaluations after reviewing the proposal. The foundation, three fixed neural candidates and sealed chronological study are implemented; their exact scope and measured evidence belong to [the neural evaluation](../../rl-neural-evaluation.md). This plan preserves proposed later milestones rather than implying forecast-cache/Jev experiments or broker execution were completed.

Goal: implement an offline, verifiable policy environment that can consume causal CPU/optional Jev forecasts, then evaluate bounded RL policies separately from forecast quality.

## Existing reuse and ownership

Reuse bar verification, calendars, causal OHLCV calculations, frozen models, source hashing and report checks. Keep old feature/model/report defaults compatible. One integration owner controls shared contracts, CLI, optional dependencies and CI. Other workers own distinct modules and tests; no parallel writer modifies the same file.

| Owner | Foundation files |
| --- | --- |
| Integration/contracts | `rl/contracts.py`; narrow `cli.py`, `pyproject.toml`, lock/CI changes |
| Data/observations | `rl/data.py`, `rl/observations.py`; narrow label-free adapter in `forecast/ohlcv_features.py` |
| Execution/accounting | `rl/execution.py`, `rl/accounting.py` |
| Environment/replay | `rl/env.py`, `rl/baselines.py`, `rl/replay.py` |
| Evidence | `rl/report.py`, meaningful `tests/test_rl_*.py`, `docs/rl.md` |

Do not extract a generic registry/framework before a second concrete consumer requires it. A small shared artifact helper may be extracted under one owner with backward-compatibility tests when both forecast and RL reports need the same primitive.

## Milestone 1: offline Gymnasium foundation and controls

Stop after a verified environment, deterministic policies and real-data development replays. No PPO, Jev pilot, learned fusion, UI expansion or broker orders.

### Task 1 — freeze contracts and inspected-period registry

Write failing tests for exact environment hashing, invalid risk/cost values, duplicate episode IDs, wrong source/config hashes and explicit inspected-date rejection for confirmation. Implement frozen `EnvConfig`, `EpisodeSpec`, `ExecutionScenario`, `ObservationSpec`, typed buy-notional/sell-quantity `CommittedOrder`, `Fill`, `LedgerEntry` and report schema. Each contract records its version and input/config identity. The inspected registry includes September 1–30, 2026 and all existing exploratory data; inspection state is never inferred from a filename alone.

Define proposed APIs:

- `EpisodeCatalog.from_verified_bars(manifest, bars, split_manifest) -> EpisodeCatalog`
- `ObservationBuilder.build(decision_at, ledger, market_window, forecast_inputs) -> Observation`
- `ExecutionModel.execute(order, execution_bar, scenario, cash_limit) -> ExecutionResult`
- `apply_fill(ledger, fill) -> LedgerState`
- `mark_to_market(ledger, available_price, available_at) -> LedgerState`
- `replay_policy(environment, policy, episode_spec) -> EpisodeLedger`

Validate field definitions and timestamp/Decimal rounding choices before workers depend on them. Proposed research defaults are explicitly listed in the architecture, not treated as user policy requirements.

### Task 2 — label-free data adapter and causal observation builder

Write tests that mutate future prices/highs/lows/volumes/labels and confirm unchanged earlier observations; test late availability, missing minutes, prior-session references, half days and day boundaries. Reuse existing OHLCV calculations through an as-of adapter without serializing labeled `ForecastExample` fields into policy state. Fit/freeze training-only normalization and expose finite Float32 vectors with missing masks. Exclude declared warmup consistently across all policies, using past data only. Freeze eligible episodes before rewards are examined.

### Task 3 — execution and exact ledger

Write hand-calculated fixtures before implementation. A zero-slippage round trip with ten shares at $100 and $1 fee on each side, from $10,000 cash, must finish at $9,998 with reward sum -2 initial-equity bps. Add a separate adverse-slippage fixture, resizing, rejected/partial fills, quantity rounding, cash limits and loss-lock tests. Specify and expose `last_committed_target_level`: initialize flat; update on valid risk-projected commitment even if fill rejects/partially executes; canceled remainder never invisibly retries. Nonzero repeat is HOLD except independent risk projection; FLAT repeats residual share liquidation. Tests cover equal holdings with distinct visible latches, failed/partial commitments, projected targets and retry semantics. Repeating a level must not add another budget or induce automatic micro-rebalancing.

Implement buy-notional and sell-share commitments. FLAT/forced exits commit held shares so both upward/downward gaps preserve correct flattening intent; partial capacity leaves recorded residuals. Distinguish commitment/execution increase limits from marked exposure drift and delayed correction.

Implement a common regular grid and one-full-minute delayed opening fill; publish fill information only after its execution bar is available. Require all consumed inputs available by the decision tick; late required anchors submit no order and truncate explicitly. Late optional forecasts mask/fallback. Execution/next-bar reports must be available by the scheduled transition or the replay truncates/unresolves. Add 09:31 anchor/09:32:30 receipt and late forecast/terminal-window fixtures. No fill may be backdated. All policies use the same engine. Capacity/cost values are explicitly synthetic. No missing-price interpolation, negative cash/shares, unlimited leverage, optimistic stops or free terminal liquidation. Tests must cover gap overshoot and unresolved terminal holdings. Sum gross P&L, execution drag and explicit fees to net ledger changes; do not subtract costs twice.

### Task 4 — Gymnasium adapter

Add `sim` extra for Gymnasium, preserving default imports/Docker. Implement `TradeCopilotEnv` with `reset(*, seed, options)` and five-value `step(action)` results, fixed spaces and `super().reset(seed=seed)`. Use absolute target-level actions, recorded deterministic risk projection and feasible-action hints. Check invalid actions, repeat seeds, terminal/truncated semantics, forced-exit windows and reset isolation. A PPO algorithm may ignore masks; the core must enforce limits regardless.

Run Gymnasium's checker. SB3's checker belongs to the later optional RL extra. Forbid HTTP/provider/Keychain/broker access during environment construction/reset/step through tests using raising stubs and a no-network integration run.

### Task 5 — common controls, ledgers and immutable reports

Implement cash, capped intraday buy-and-hold, seeded random diagnostic and one frozen causal market-feature policy through the same clock/ledger. MARKET_ONLY mode proves the simulator without teacher calls. CPU-cache mode and a forecast-driven control are added only after Task 6 creates eligible caches; missing optional Jev inputs retain all registered episodes with explicit masks/fallback, never selective profitable-case omission.

Proposed lazy CLI commands are `rl validate-env`, `rl benchmark`, `rl evaluate` and later `rl train`. They require explicit verified inputs, config, split and output paths. Replays publish full private ledgers and aggregate reports with immutable atomic writes. Report loaders verify digests and safe paths without policy loading or inference. Test corrupt/tampered bundles, existing-output refusal, path traversal, sum-reward/equity reconciliation and aggregate recomputation.

Replace baseline CI `--all-extras` with explicit current extras; add a dedicated `sim` test job and Gymnasium checker. Baseline tests skip optional modules with `importorskip`/conditional collection; optional module typing uses lazy imports and narrowly scoped explicit treatment. Simulation/RL jobs type-check those modules with their dependencies installed, rather than silently disabling strict typing. Confirm minimal package import and Docker/no-network report serving still work. Register max episodes/steps/time/storage for replay. Benchmark local throughput after correctness passes; publish measurements rather than claiming performance targets.

### Foundation acceptance

An adversarial profitable-looking residual that cannot exit must block improvement status, not evade closing costs. All accounting/causality/resource/integrity fixtures pass; Gymnasium checker passes; deterministic golden trajectories repeat; no network/credential/order calls occur; controls use identical episodes/costs/capital; real-data development reports preserve unsuccessful/zero-trade/unresolved outcomes. The first milestone is environment readiness, not forecast improvement or profitable trading.

## Milestone 2: eligible forecasts and Jev context experiments

### Task 6 — out-of-fold CPU cache

Create immutable `ForecastArtifact`/cache contracts with input/model/scaler/calibrator identities, logical as-of, actual generation time, fitting-label cutoffs, availability mode and expiry. Extend teacher preparation with expanding chronological folds: fit only earlier matured labels, calibrate on a separate earlier block, then freeze predictions for the next episode block. Initial insufficient-history sessions are declared warmup. Tests reject in-sample/future-fit/late/stale/misaligned artifacts. Do not use the current full-development-refitted model for earlier development episodes.

Environment consumes cache data only, never a forecaster callback. Distinguish `MARKET_ONLY`, `CPU_CACHE` and actual Jev-input profiles in reports. Historical model-generation and retrospective availability assumptions remain explicit; no fabricated historical inference timestamp is allowed. Preserve actual `generated_at`, with a separate hypothetical `replay_effective_available_at` and assumption hash. Prospective mode admits only actual completion/receipt before decision. Verify fitting IDs/hashes against manifests and retain unknown vendor pretraining cutoff as unknown.

### Task 7 — context v2, retrieval and typed labels, offline first

Own `forecast/context.py`, `forecast/retrieval.py`, `forecast/questions.py`, `forecast/store.py` and corresponding tests under separate non-conflicting responsibilities. Keep existing v1 defaults. Compute/bucket numeric features locally; bounded recent normalized bars plus summaries, missingness and source timestamps. Retrieve three prior completed analogues with training-only scaling and strict matured-label cutoff. Preserve target-definition distinctions between minute-close proxy and quote-derived last trade.

Implement direction and one separately defined adverse-price-event question; labels are calculated locally in a separate outcome object. Risk labels require a complete path; strict below-threshold is YES, equality NO, unavailable/late path is unavailable, and label availability cannot be moved backward. Extend the direction-only response validator with an explicit v2 Noul contract: `answer["type"] == "noul"` and finite `answer["noul"]` in [0,1], without assuming Choice `probabilities` or `confidence` fields. Request criteria use `"true"`/`"false"`. Test exact boundaries, missing risk paths, query exclusion/overlap, deterministic context/index hashes, payload byte caps, option-order mappings and malformed response rejection. Masked date/ticker variants remain retrospective leakage mitigations, not proof of uncontaminated provider knowledge.

### Task 8 — separately reviewed paid pilot, then fusion only with adequate evidence

Before any request, freeze 20 representative case IDs using only permitted metadata/as-of information, v1/v2 pairs and ten robustness checks. Proposed caps: 50 attempts/$0.15 aggregate, existing ten-request/$0.05 per-run limits, shared 100-attempt cap unchanged. Failed requests count; retries cannot silently expand budget. Recheck actual credits/remaining attempts and obtain explicit pilot authorization. No calls are made by this plan.

Measure paired proper scores, accuracy, coverage, cost and schema stability. A 20-case pilot is feasibility evidence only. Adequate additional chronological teacher labels are prerequisite for learned CPU+Jev fusion or distillation. Compare CPU-only, Jev-only and hybrid on identical untouched cases. Train stacking with out-of-fold outputs and calibrate separately. Environment training continues with cached inputs and makes zero API calls.

## Milestone 3: bounded PPO and fresh policy evaluation

### Task 9 — pretraining registration, optional training and trusted local checkpoints

Before any training, write and validate a registration artifact independent of future dataset hashes. Freeze exact new dates/symbols, eligible decision times, missing/exclusion rules, policy candidates/seeds, reward/execution/risk/cost settings, comparator selection and pass criteria. Store its hash and enforce protected-data read restrictions. Dataset acquisition later binds source hashes without rewriting registration. Freeze selected checkpoint/config hashes before releasing confirmation outcomes. Any confirmation period inspected while implementation/tuning continues is retired as development and replaced by a newly registered future block.

Add `rl` extra for compatible pinned SB3/SB3-Contrib/torch; baseline CI/default Docker must not install torch. Lazy imports produce actionable missing-extra errors. Run SB3 checker, a tiny CPU smoke and saved/restored action parity. Accept only locally produced, hash-pinned supported policy artifacts; a checksum alone does not make arbitrary pickle/torch loading safe. Report serving never loads a policy.

Run a registered three-candidate comparison: PPO64→64, PPO256→256, and RecurrentPPO with separate one-layer256 LSTMs plus256→128 actor/critic heads. The last uses `shared_lstm=False`, `enable_critic_lstm=True`; defer two-layer LSTMs until development evidence warrants a new comparison. First verify compatible stable dependency versions in the lock and CPU operators. Benchmark CPU/MPS capability and steady-state throughput on training/synthetic data, with deterministic inference parity and operator-support checks; choose the device before reviewing outcome quality.

Predeclare seeds42/43/44, common observations/dates/costs/optimizer settings, one worker, initial proposal100,000 steps per seed and600-second hard cap. Use the slowest candidate's measured throughput to freeze a feasible shared step budget before training. Log actual steps/updates/time/device/memory and every stopped run; unequal-step stopped runs cannot be called a fair equal-step comparison. Parameter counts differ, so superior recurrent results do not alone prove memory rather than capacity caused the difference. These are research proposals, not tuned values, and cannot be expanded after favorable or unfavorable validation results. Recurrent evaluation must retain returned `state` and pass `episode_start`; reset on terminal/truncated episodes, symbol/date changes and only completed vector lanes. Initial hidden state is zero at the same first eligible decision as the controls. Add tests for boundary/history invariance, carry-state versus reset-every-step behavior on a controlled memory fixture, lane isolation, rollout padding masks and saved/restored deterministic trajectory parity. Restore normalization only from training and freeze all its statistics during evaluation; checkpoint selection uses tuning only. Resume requires verified unchanged inputs/config and records any RNG/reproducibility limitations.

### Task 10 — frozen confirmation and comparative scorecards

Existing April–September prices are development data. Require the completed Task 9 pretraining registration and frozen selection before confirmation data release; a prospective candidate is 30 regular sessions from October5, 2026 after exchange-calendar verification. This is not an automation or completed data acquisition. Do not use the inspected September final test as fresh confirmation for RL.

Compare cash, capped intraday hold and strongest predeclared rule with PPO CPU under identical episodes/execution/costs. Add CPU+Jev rule/PPO only when adequate valid cache coverage exists. Report every seed, net returns/drawdown/exposure/turnover/trades, costs and unresolved/rejected events. Cash Sharpe is N/A. Bootstrap paired daily differences with symbols grouped and contiguous-block sensitivity; stress doubled/quadrupled friction. Proposed policy-improvement gates are stated in the architecture and cannot be adjusted after test. Every registered episode must be valid and resolved; any residual/invalid episode blocks improvement claims while remaining in diagnostics. Failed or inconclusive policy comparisons are preserved.

Run the independent 80% forecast gate separately; an RL profit result cannot pass it. A later paper/live execution adapter is outside this plan and requires its own authorization, measured delivery/fill reconciliation and risk design.

## Review and release checkpoints

Each milestone receives independent spec and code review, meaningful tests, Ruff/strict typing, packaging and appropriate no-network validation. Report actual executed checks separately from intended future tests. Publish only aggregates and figures; source bars, cases, credentials, forecast vectors and private ledgers remain local. Final confirmation data is scored once with frozen settings. Build requests, broker actions and production promotion are never implied by an offline plan.
